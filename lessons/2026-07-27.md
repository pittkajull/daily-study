## Tujuan Belajar

Setelah membaca, pembaca memahami siklus hidup software, pemisahan tanggung jawab, dan alasan engineering practices diperlukan.

## Prasyarat

Bisa membaca kode dasar dan memahami variabel, fungsi, serta input-output.

## Teori: Apa yang Dipelajari?

Software engineering bukan sekadar menulis kode yang bisa berjalan. Ia adalah disiplin untuk mengubah kebutuhan pengguna menjadi sistem yang dapat diandalkan, diuji, dipantau, dan dipelihara. Kode akan dibaca jauh lebih sering daripada ditulis, sehingga struktur dan keputusan desain sama pentingnya dengan hasil akhirnya.

Dalam proyek nyata, kebutuhan berubah, anggota tim berganti, dan jumlah pengguna bertambah. Karena itu engineer memakai version control, code review, automated testing, dokumentasi, logging, dan arsitektur yang memisahkan aturan bisnis dari detail teknis. Tujuannya bukan membuat kode paling rumit, melainkan mengurangi biaya perubahan dan risiko kerusakan.

## Kenapa Ini Penting?

Agar kode mudah dipahami, diuji, dan dikembangkan oleh tim.

## Ringkasan Bacaan Terbaru

Baca sumber asli untuk konteks terbaru.

## Contoh Praktik

```text
def calculate_total(items):
    return sum(item['price'] * item['qty'] for item in items)
```

Fungsi calculate_total menerima daftar item, menghitung harga dikali jumlah untuk setiap item, lalu menjumlahkan seluruh hasil. Aturan bisnis ini sebaiknya tidak bergantung pada database atau tampilan agar dapat diuji secara mandiri. Setelah itu tambahkan test untuk daftar kosong, satu item, diskon, dan jumlah yang tidak valid.

## Best Practices

Gunakan nama jelas, fungsi kecil, version control, code review, dan automated tests.

## Kesalahan Umum

Fungsi terlalu besar, duplikasi kode, dan tidak menangani edge case.

## Latihan Mandiri

Buat fungsi kecil dan tambahkan tiga unit test.
